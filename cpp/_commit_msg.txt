修复支持库进度失真（40% 卡住后跳校验）+ 分片进度缺失

用户实测两个问题：
1. 支持库步骤进度 40% 多就进校验（实际已下载完成）——字节 0/0KB
2. 快下载完时 UI 卡住几十秒（实为进度失真导致的停滞感）

根因（两个 bug 叠加）：
1. 【总量丢失】阶段 B 的 startAssets 重置 m_categoryTotalBytes[1]=0
   ——阶段 B 的 collectTasks 只有 assets 任务，重置后 cat1 不再恢复
   → 支持库步骤总量变 0/0KB，进度分母丢失
   → 修复：阶段 B 不再重置 libs 总量（阶段 A 已统计）
2. 【分片进度缺失】夸父 fileProgress 上报"分片线程接收量"
   （received 从 Range 起始算）——多分片文件各报各的，上层按 savePath
   去重只累计第一个分片 → 大文件（26.2.jar 39MB）字节几乎不计入
   → 支持库进度只反映小文件部分（40%）
   → 修复：fileProgress 上报"文件级总进度"（file->totalDone() /
   file->fileSize）；文件完成（mergeFile 成功）后补发满字节帧，
   让进度精确到 100%
