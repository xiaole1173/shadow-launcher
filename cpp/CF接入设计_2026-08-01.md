# CurseForge 接入设计（CF 适配器）— 2026-08-01

## 一、实测结论（决定方案可行性）

| 项 | 结果 |
|---|---|
| CF API 直连（api.curseforge.com） | 搜索 4~13s（波动），分类 1~10s——**慢但可用**（司南引擎缓存后二次秒开） |
| 镜像代理 | mcimirror 无 CF 代理（404）→ 只能直连 |
| 下载源 edge.forgecdn.net | **3.9s / 1.4MB**（~360KB/s）✓ 可达 |
| 图标 CDN media.forgecdn.net | **1.7s / 16KB** jpeg ✓ 可达（走司南图标管线） |
| 文件列表 | **自带 downloadUrl**（无需额外端点）；gameVersions 混着版本/加载器/环境（如 ['Client','1.20.1','Forge']） |
| 分类 | classId：Mods=6、RP=12、**Shaders=6552（独立类）**、Modpacks=4471 |
| 加载器过滤 | `modLoaderType` 参数有效：1=Forge 4=Fabric 5=Quilt 6=NeoForge |

## 二、数据模型统一（QML 零改动显示）

CF 搜索响应 → 统一 QVariantMap（与 Modrinth 的 `parseSearchResponseItems` 输出同构）：
```
{ slug: QString::number(modId),   // 数字 id 作 slug（与 Modrinth 字符串 slug 天然不冲突）
  title: name, desc: summary,
  icon: logo.thumbnailUrl,         // 256x256 jpeg → 司南图标管线
  downloads: downloadCount,
  versions: 从 latestFiles[0].gameVersions 提取 MC 版本（逗号串）,
  loader: 从 latestFiles[0].gameVersions 提取加载器,
  dateModified: dateModified,
  source: "CurseForge" }           // 卡片右上角来源标签（现有 source 字段，改从 model 读）
```

## 三、分类叠加（难点 1 方案）

- 每个 tab 的"分类"下拉 = **Modrinth 分类 + CF 分类叠加**
- CF 选项 label 加 `CF·` 前缀（如 "CF·Adventure and RPG"），值用 `cf:{categoryId}`（如 `cf:422`）
- 搜索时判断：值以 `cf:` 开头 → **只搜 CF**（categoryId 过滤）；否则只搜 Modrinth；**空（全部）→ 双源并行聚合**
- CF 分类**硬编码静态表**（从 API 实测提取，避免启动慢请求）：
  - Mods(6)：422 Adventure and RPG, 412 Technology, 419 Magic, 406 World Gen, 434 Armor Tools Weapons, 420 Storage, 421 API and Library, 423 Map and Information, 436 Food, 6814 Performance, 6821 Bug Fixes, 424 Cosmetic, 425 Miscellaneous, 435 Server Utility, 426 Addons, 5191 Utility & QoL, 4558 Redstone, 4906 MCreator, 4671 Twitch Integration, 8937 ModJam 2025, 5299 Education, 9026 CreativeMode, 10775 Horror
  - Shaders(6552)：6553 Realistic, 6554 Fantasy, 6555 Vanilla
  - RP(12)：393~405 分辨率/风格 17 个
  - Modpacks(4471)：预留（任务 2 用）

## 四、双源聚合搜索（难点 2 方案）

- `searchModsEx` 等：Modrinth + CF **并行请求**，两者都回（或 8s 超时兜底）后合并 emit 一次
- 排列：**Modrinth 组在前、CF 组在后**，各自按下载量降序（downloads 不可跨源比较，不混排）
- 卡片右上角来源标签沿用（Modrinth / CurseForge）
- 分页/预取：QML 层无感（后端聚合，offset 双源各自维护）

## 五、详情页整合（难点 3 方案）

- **不跨源合并**：从哪个源的卡片点进，就看哪个源的详情/版本/下载（重复模组两源并存，来源标签区分，用户自选）
- CF 版本列表：`/v1/mods/{id}/files?gameVersion=X&modLoaderType=Y` → 按加载器分组展示（Forge/Fabric/Quilt/NeoForge）
- CF 下载：文件自带 `downloadUrl` → 直下（edge.forgecdn.net）
- 判断：详情页 slug 为纯数字 → CF 路径；否则 Modrinth

## 六、overlay 修改（难点 4）

- 清除详情页顶部"来源：???"文字（双源已完整接入，来源标签在卡片上已有）

## 七、实现文件

- `src/core/cf_api.h/.cpp`（新）：CfApi 客户端（走司南引擎 getJson + x-api-key 头），分类静态表，统一模型转换
- `src/core/resource_fetch_engine.h/.cpp`：getJson 加可选 headers
- `src/backend/resource_backend.h/.cpp`：双源聚合搜索 + CF 版本/文件接口（fetchModVersionsCf 等）
- `qml/DownloadPage.qml`：分类叠加、source 从 model 读、详情页 CF 分支
- `qml/ModDetailPage.qml` / `ShaderDetailPage.qml` / `ResourcePackDetailPage.qml`：CF 版本/下载
- `tests/test_cf_api.cpp`（新）：CF 搜索/解析自测
