# 下载进度显示系统重构方案

> 2026-07-24 诊断结论：纯 MC 下载的进度显示活在 C++ 后端的两套系统的交界处，数据流混战，QML 层如实渲染了混乱数据。

---

## 当前问题

### 纯 MC 下载有三条数据流在打架

```
数据流 A: m_dlStates (旧系统)
  updateDownloadProgress() ───→ m_dlStates[versionId]
  verifyProgressChanged   ───→ (更新 verify 进度)
  onVersionDownloadFinished──→ (清理)
  
数据流 B: ds->steps (新管线)
  installVersion() ───→ 手动塞 4 个 pending 步骤
  updateStep()      ───→ ❌ 只更新 merged 安装，跳过纯 MC
  → ds->steps 永远 4 个 pending

数据流 C: updateCardFromSession (中介)
  progressUpdated 信号(100ms throttle)──→ toCard() 复制 ds->steps
  → ds->steps 始终 pending → 传给 model → 子步骤无状态变化
```

| 阶段 | 实际进度 | ds->steps 状态 | 子步骤 UI |
|------|---------|---------------|-----------|
| 下载版本 JSON | OK (m_dlStates) | pending | ○ 灰点不动 |
| 下载库文件 | OK (m_dlStates) | pending | ○ 灰点不动 |
| 下载资源文件 | OK (m_dlStates) | pending | ○ 灰点不动 |
| 校验 | OK (m_dlStates) | pending | ○ 灰点不动 |

### 卡片重建两路冲突（尚未完全解决）

- `updateCardFromSession()` — 增量更新，纯 MC 专属
- `doRebuildInstallCards()` — 全量重建，Section 2 虽跳过了 DS 版本，但 Section 1（merged）和 `catsFullyDone` 触发的全量 `rebuildInstallCards()` 仍可能意外覆盖
- 结果：卡片状态来回跳 + 闪烁

---

## 重构目标

**单一数据源（ds->steps）、单一卡片更新路径（updateCardFromSession）、废除 m_dlStates 在纯 MC 显示中的角色。**

| 维度 | 旧方案 | 新方案 |
|------|-------|-------|
| 步骤数据源 | m_dlStates + ds->steps 双份 | **仅 ds->steps** |
| 进度更新路径 | m_dlStates ← updateDownloadProgress → doRebuildInstallCards | **ds->steps ← updateStep() → updateCardFromSession** |
| 卡片创建方式 | Section 2 用 DlState 构建 QVariantList | **updateCardFromSession 从 ds->toCard() 获取** |
| 速度追踪 | m_dlStates 自建滑动窗口 | **ds->recordBytes() per-session 滑动窗口** |
| StepPipeline | 仅 merged 安装使用 | **纯 MC 也用** |

## 详细改动方案

### 改动 1：`installVersion()` — 纯 MC 改用 `rebuildSteps()` 启动管线

**位置**：`version_backend.cpp` 约第 1215 行

**当前代码**：
```cpp
// — Populate initial steps for the download card —
{
    auto* ds = ensureSession(versionId);
    if (ds) {
        QVariantList steps;
        auto addStep = [&](const QString& name) {
            steps.append(QVariantMap{...});
        };
        addStep(tr("下载版本JSON"));
        addStep(tr("下载支持库"));
        addStep(tr("下载资源文件"));
        addStep(tr("校验游戏资源完整性"));
        ds->steps = steps;
        updateCardFromSession(versionId, versionId, "version");
    }
}
```

**改为**：
```cpp
// — Build step pipeline for pure MC download —
{
    auto* ds = ensureSession(versionId);
    if (ds) {
        rebuildSteps(versionId,
            {tr("下载版本JSON"), tr("下载支持库"), tr("下载资源文件"), tr("校验游戏资源完整性")},
            {1.0, 3.0, 5.0, 1.0},  // 权重同 merged 安装的 MC 部分
            {false, true, true, true}  // JSON 步骤下载前隐藏, 其他显示
        );
        // 立即暴露卡片 (不等 HTTP 首字节)
        updateCardFromSession(versionId, versionId, "version");
    }
}
```

**效果**：纯 MC 下载启动 StepPipeline，StepNode 驱动加权进度（0→1.0），`ds->smoothProgress` 实时可用。

### 改动 2：`updateDownloadProgress()` — 纯 MC 也走 updateStep

**位置**：`version_backend.cpp` 约第 3277 行

**当前代码**：
进度回调 `progressChanged` 中遍历 sessions 查找 merged 安装更新 steps，对纯 MC 只做 `ds->recordBytes()` + 更新 `m_dlStates`。

**改为**：
在 `updateDownloadProgress()` 末尾（已对 merged 分支有完整 updateStep 逻辑之后），添加纯 MC 分支：

```cpp
// — Pure MC: route category progress into ds->steps via updateStep —
if (!mergedSessionId.isEmpty()) {
    // 已有关联 merged session 的处理逻辑...
} else {
    // Pure MC download — update ds->steps directly
    auto* ds = dlSession(versionId);
    if (ds && ds->steps.size() >= 4) {
        // Step 0 (JSON): mark completed once any bytes flow
        if (db > 0 && ds->steps[0].toMap()["status"].toString() != "completed") {
            updateStep(versionId, 0, "completed", 100, catBytes[0], catTotals[0]);
        }
        // Step 1 (libraries): category index 1
        updateStep(versionId, 1, catStatus(1), catPct(1), catDl(1), catTot(1));
        // Step 2 (assets): category index 2
        updateStep(versionId, 2, catStatus(2), catPct(2), catDl(2), catTot(2));
    }
}
```

**辅助函数**（局部 lambda）：
```cpp
auto catStatus = [&st](int ci) -> QString {
    if (st.catBytesTotal[ci] <= 0)
        return st.bytesDl > 0 ? "completed" : "pending";  // empty category
    return st.catBytesDl[ci] >= st.catBytesTotal[ci] ? "completed" : "active";
};
auto catPct = [&st](int ci) -> int {
    return st.catBytesTotal[ci] > 0 ? (int)(st.catBytesDl[ci] * 100 / st.catBytesTotal[ci]) : 0;
};
```

**注意**：不能在 `progressChanged` lambda 中直接添加——该 lambda 同时被纯 MC 和 merged 共享。需要用一个 run-time 判断 `isMerged` 来分流。建议将纯 MC 分支独立封装成一个函数 `updateStepForVersionDownload(versionId)`。

### 改动 3：`verifyProgressChanged` 回调 — 纯 MC 也走 updateStep

**位置**：`version_backend.cpp` 约第 1475 行

**当前代码**：
```cpp
// 只对 merged 安装调 updateStep/showStep
for (auto sit = m_downloadSessions.begin(); ...) {
    if (d && d->isMerged() && d->mcVersion == versionId) {
        // 标记步骤 0-2 completed
        for (int i = 0; i < 3 && i < d->steps.size(); i++)
            updateStep(sit.key(), i, "completed", 100);
        showStep(sit.key(), verifyIdx);
        updateStep(sit.key(), verifyIdx, "active", pct, checked, total);
        break;
    }
}
// standalone: 只调 syncPrimaryProgress + rebuildInstallCards
syncPrimaryProgress();
rebuildInstallCards();
```

**改为**：
添加纯 MC 分支，`else if (dlSession(versionId))`：

```cpp
// 纯 MC: 通过 ds->steps 管线更新
auto* pureDs = dlSession(versionId);
if (pureDs && !pureDs->isMerged()) {
    for (int i = 0; i < 3 && i < pureDs->steps.size(); i++)
        updateStep(versionId, i, "completed", 100);
    int verifyIdx = 3;
    if (verifyIdx < pureDs->steps.size()) {
        showStep(versionId, verifyIdx);
        int pct = total > 0 ? (checked * 100 / total) : 0;
        updateStep(versionId, verifyIdx, "active", pct, checked, total);
    }
}
```

**同时废除** `syncPrimaryProgress()` + `rebuildInstallCards()` 的全量重建调用（因为 `updateStep` 已触发增量更新）。

### 改动 5：`doRebuildInstallCards()` — 清理 Section 2

**位置**：`version_backend.cpp` 约第 7982 行

**当前代码**：
```cpp
// 2. Version cards
for (const QString& vid : m_activeIds) {
    if (seen.contains(vid)) continue;
    if (m_downloadSessions.contains(vid)) continue;  // ← fdc3a4f 加的跳过
    seen.insert(vid);
    
    InstallCard c;
    // ... ~200 行从 m_dlStates 构建卡片的复杂逻辑 ...
}
```

**改为**：**直接删除整个 Section 2**（不再构建纯 MC 卡片）。

为什么安全：所有纯 MC 卡片现在都由 `updateCardFromSession()` 通过 DS 管线管理。Section 1（merged 安装）和 Section 3（user data import）保留不动。

注意：Section 2 也负责**没有 DS 的版本**（比如 `m_activeIds` 中某些特殊阶段）。检查 `m_activeIds` 中是否还有不经过 DS 的路径——如果 `installVersion` 重构后确保每个纯 MC 版本都有 DS，则删除安全。

**迁移策略**：如果担心某些角落没有 DS 的版本，可保留 Section 2 的 `m_downloadSessions.contains(vid)` 跳过逻辑但把内部改为从 DS 读取（而不用 m_dlStates）。

### 改动 7：`DownloadQueueCard.qml` — 模型字段 fallback 确认

当前代码：
```qml
Repeater {
    model: model.steps || []
    delegate: RowLayout {
        visible: modelData && modelData.show !== false
```

`model.steps || []` 是为了 model.steps 为 null 时的安全 fallback。如果 `updateCardFromSession` 总能提供有效的 `steps`（至少空 `QVariantList`），这个 fallback 不需要，但保留无害。

**建议**：确认 `toCard()` 中 `card.steps = steps;` 永远不会为 null（空列表即可），然后 `|| []` 可移除但非必须。

## 改动后数据流

```
installVersion("26.2")
  └─ ensureSession("26.2") → DS
  └─ rebuildSteps(4 steps, weights, showFlags) → StepPipeline
  └─ updateCardFromSession → appendRow → 卡片立即出现 (4个pending)

version_downloader progressChanged
  └─ updateDownloadProgress
      └─ ds->recordBytes(db, tb)  // 速度追踪
      └─ updateStepForVersionDownload(versionId)
          └─ updateStep(versionId, 1, "active", 45%, ...)  // 库下载进度
          └─ updateStep → ds->steps[1] 更新
              └─ updateCardFromSession → updateRow → UI更新

version_downloader verifyProgressChanged
  └─ completed: updateStep x3 → 标记步骤 0-2 为 completed
  └─ showStep(verifyIdx) → 显示校验步骤
  └─ updateStep(verifyIdx, "active", pct) → 实时校验进度

onVersionDownloadFinished
  └─ success: updateStep(verifyIdx, "completed") → 全部完成
  └─ cancel: ds->markFailed("已取消") → 显示失败状态

updateCardFromSession (100ms throttle)
  └─ toCard() → card.steps = ds->steps (最新)
  └─ model steps 原地字段同步 → updateRow → QML增量更新

QML 层
  └─ Repeater { model: model.steps } → 4 个子步骤
     ○ pending: 灰点
     ● active:  蓝点 + 百分比
     ✓ completed: 绿点
```

---

## 需要废弃的代码

1. `installVersion()` 中的手动塞 4 个 QVariantMap 的代码块（被 `rebuildSteps()` 替代）
2. `doRebuildInstallCards()` 中 Section 2 的纯 MC 卡片构建（~200 行复杂的 m_dlStates 读取逻辑）
3. 纯 MC 下载的 `m_dlStates` 中用于显示进度的字段（`progress`, `catBytesDl/Ttl`, `verifyChecked/Total`）在显示层的读代码——`m_dlStates` 仍保留用于速度衰减和日志，但不再参与卡片构建
